alert-service owns weather warnings: alerts for a city with a vigilance level (yellow, orange, red), and the notifications sent to users about an alert.

## At a glance

| Item | Value |
| --- | --- |
| Owner | Member 5 |
| Entities | Alert and Notification |
| Stack | Java 21, Spring Boot 4.0.8, Spring Data JPA (Hibernate), Bean Validation, Eureka client |
| Port | 8085 (clients use the gateway on 8090) |
| Database | MySQL, schema `alert_db` |
| Eureka name | `alert-service` |
| REST resources | `/api/alerts`, `/api/notifications` |
| Base package | `com.meteo.alert` |

## Entities

Both entities live in package `com.meteo.alert.entity`. "Required" means the field must be present and not empty in a POST or PUT body.

### Alert

Stored in table `alerts`. REST resource `/api/alerts`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | long | auto | generated by the database |
| title | string | yes | max 150 characters |
| description | string | no | max 1000 characters |
| type | AlertType | yes | one of HEAT_WAVE, STORM, HEAVY_RAIN, FLOOD, STRONG_WIND, SNOW, SANDSTORM, FOREST_FIRE_RISK |
| severity | Severity | yes | one of YELLOW, ORANGE, RED |
| cityId | long | yes | id of a City in geo-service, not checked |
| startTime | date-time | yes | — |
| endTime | date-time | no | — |
| active | boolean | no | default true |

### Notification

Stored in table `notifications`. REST resource `/api/notifications`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | long | auto | generated by the database |
| userId | long | yes | id of a User in user-service, not checked |
| channel | NotificationChannel | yes | one of EMAIL, SMS, PUSH |
| message | string | yes | max 500 characters |
| status | NotificationStatus | yes | one of PENDING, SENT, FAILED, READ; default PENDING |
| createdAt | date-time | auto | set by the server at creation |
| alert | Alert | yes | send `{"id": 1}`; must exist; foreign key `alert_id` |

## REST API

Through the gateway: `http://localhost:8090`. Direct, for debugging: `http://localhost:8085`.

| Method | Path | Action | Success | Errors |
| --- | --- | --- | --- | --- |
| GET | `/api/alerts` | list all; `?cityId=` filters | 200 | — |
| GET | `/api/alerts/{id}` | get one Alert | 200 | 404 |
| POST | `/api/alerts` | create | 201 | 400 |
| PUT | `/api/alerts/{id}` | replace | 200 | 400, 404 |
| DELETE | `/api/alerts/{id}` | delete | 204 | 404, 409 |
| GET | `/api/notifications` | list all; `?userId=` filters | 200 | — |
| GET | `/api/notifications/{id}` | get one Notification | 200 | 404 |
| POST | `/api/notifications` | create | 201 | 400, 404 |
| PUT | `/api/notifications/{id}` | replace | 200 | 400, 404 |
| DELETE | `/api/notifications/{id}` | delete | 204 | 404 |

Example: create an Alert with `POST /api/alerts`

```json
{
  "title": "Strong wind warning",
  "description": "Gusts up to 80 km/h expected along the coast.",
  "type": "STRONG_WIND",
  "severity": "ORANGE",
  "cityId": 1,
  "startTime": "2026-11-11T06:00:00",
  "endTime": "2026-11-11T20:00:00",
  "active": true
}
```

Response `201 Created`:

```json
{
  "id": 1,
  "title": "Strong wind warning",
  "description": "Gusts up to 80 km/h expected along the coast.",
  "type": "STRONG_WIND",
  "severity": "ORANGE",
  "cityId": 1,
  "startTime": "2026-11-11T06:00:00",
  "endTime": "2026-11-11T20:00:00",
  "active": true
}
```

Example: create a Notification with `POST /api/notifications`

```json
{
  "userId": 1,
  "channel": "EMAIL",
  "message": "Orange alert: strong wind in Tunis tomorrow.",
  "status": "PENDING",
  "alert": {
    "id": 1
  }
}
```

Response `201 Created`:

```json
{
  "id": 1,
  "userId": 1,
  "channel": "EMAIL",
  "message": "Orange alert: strong wind in Tunis tomorrow.",
  "status": "PENDING",
  "alert": {
    "id": 1,
    "title": "Strong wind warning",
    "description": "Gusts up to 80 km/h expected along the coast.",
    "type": "STRONG_WIND",
    "severity": "ORANGE",
    "cityId": 1,
    "startTime": "2026-11-11T06:00:00",
    "endTime": "2026-11-11T20:00:00",
```

## Rules and errors

- Every POST and PUT body is validated (`@Valid`); a broken rule returns 400 with the field list.
- An Alert that still has notifications cannot be deleted: 409 Conflict. Delete the notifications first.
- A Notification must reference an existing Alert (`alert.id`); otherwise 404 "Alert not found with id …".
- `createdAt` of Notification is set by the server; a value sent by the client is ignored.
- `cityId`, `userId` point to other services and are stored as plain numbers. This service does not check that the id exists there (an OpenFeign check can come later).
- Tables are created and updated from the entities at startup (`ddl-auto: update`).

## Links with other services

This service points to:

- Alert.cityId → City in geo-service
- Notification.userId → User in user-service

Other services that depend on it:

- report-service: read to build reports (Alert)

## Configuration

`src/main/resources/application.yml`; values in `${...}` can be overridden by environment variables.

```yaml
server:
  port: 8085

spring:
  application:
    name: alert-service
  datasource:
    url: jdbc:mysql://${DB_HOST:localhost}:3306/alert_db?createDatabaseIfNotExist=true&allowPublicKeyRetrieval=true&useSSL=false
    username: ${DB_USERNAME:meteo}
    password: ${DB_PASSWORD:meteo}
  jpa:
    hibernate:
      ddl-auto: update      # creates/updates the tables from the entities (dev only)
    show-sql: true
    open-in-view: false

eureka:
  client:
    service-url:
      defaultZone: ${EUREKA_URL:http://localhost:8761/eureka/}
  instance:
    prefer-ip-address: true

management:
  endpoints:
    web:
      exposure:
        include: health,info
```

| Variable | Default | Used for |
| --- | --- | --- |
| DB_HOST | localhost | database host |
| DB_USERNAME | meteo | database user |
| DB_PASSWORD | meteo | database password |
| EUREKA_URL | http://localhost:8761/eureka/ | registry address |

## Run and test

1. Start the database (`docker compose up -d` at the project root) and discovery-server.
2. Run `AlertServiceApplication` from IntelliJ, or `mvn -pl alert-service spring-boot:run` from the project root.
3. Check `http://localhost:8085/actuator/health` returns `{"status":"UP"}`, and that `ALERT-SERVICE` appears on the Eureka dashboard (`http://localhost:8761`).
4. Call `GET http://localhost:8090/api/alerts` through the gateway, or run the Postman folders "alert-service / Alert" and "alert-service / Notification".
