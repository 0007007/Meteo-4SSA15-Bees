# geo-service

geo-service owns the places of the app: countries and the cities inside them. City is the hub of the whole domain: stations, air quality, forecasts, alerts, favorite places and reports all point to a city by its id.

## At a glance

| Item | Value |
| --- | --- |
| Owner | Hamza Najjar |
| Entities | Country and City |
| Stack | Java 21, Spring Boot 4.0.8, Spring Data JPA (Hibernate), Bean Validation, Eureka client |
| Port | 8081 (clients use the gateway on 8090) |
| Database | PostgreSQL, schema `geo_db` |
| Eureka name | `geo-service` |
| REST resources | `/api/countries`, `/api/cities` |
| Base package | `com.meteo.geo` |

## Entities

Both entities live in package `com.meteo.geo.entity`. "Required" means the field must be present and not empty in a POST or PUT body.

### Country

Stored in table `countries`. REST resource `/api/countries`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | long | auto | generated by the database |
| name | string | yes | max 100 characters |
| isoCode | string | yes | 2 to 3 characters; unique |
| continent | string | no | max 50 characters |

### City

Stored in table `cities`. REST resource `/api/cities`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | long | auto | generated by the database |
| name | string | yes | max 100 characters |
| latitude | decimal | yes | -90.0 to 90.0; decimal degrees |
| longitude | decimal | yes | -180.0 to 180.0; decimal degrees |
| population | integer | no | ≥ 0 |
| timezone | string | no | max 50 characters |
| country | Country | yes | send `{"id": 1}`; must exist; foreign key `country_id` |

## REST API

Through the gateway: `http://localhost:8090`. Direct, for debugging: `http://localhost:8081`.

| Method | Path | Action | Success | Errors |
| --- | --- | --- | --- | --- |
| GET | `/api/countries` | list all | 200 | — |
| GET | `/api/countries/{id}` | get one Country | 200 | 404 |
| POST | `/api/countries` | create | 201 | 400, 409 |
| PUT | `/api/countries/{id}` | replace | 200 | 400, 404, 409 |
| DELETE | `/api/countries/{id}` | delete | 204 | 404, 409 |
| GET | `/api/cities` | list all; `?countryId=` filters | 200 | — |
| GET | `/api/cities/{id}` | get one City | 200 | 404 |
| POST | `/api/cities` | create | 201 | 400, 404 |
| PUT | `/api/cities/{id}` | replace | 200 | 400, 404 |
| DELETE | `/api/cities/{id}` | delete | 204 | 404 |

Example: create a Country with `POST /api/countries`

```json
{
  "name": "Tunisia",
  "isoCode": "TN",
  "continent": "Africa"
}
```

Response `201 Created`:

```json
{
  "id": 1,
  "name": "Tunisia",
  "isoCode": "TN",
  "continent": "Africa"
}
```

Example: create a City with `POST /api/cities`

```json
{
  "name": "Tunis",
  "latitude": 36.8065,
  "longitude": 10.1815,
  "timezone": "Africa/Tunis",
  "country": {
    "id": 1
  }
}
```

Response `201 Created`:

```json
{
  "id": 1,
  "name": "Tunis",
  "latitude": 36.8065,
  "longitude": 10.1815,
  "timezone": "Africa/Tunis",
  "country": {
    "id": 1,
    "name": "Tunisia",
    "isoCode": "TN",
    "continent": "Africa"
  }
}
```

## Rules and errors

- Every POST and PUT body is validated (`@Valid`); a broken rule returns 400 with the field list.
- A Country that still has cities cannot be deleted: 409 Conflict. Delete the cities first.
- `isoCode` must be unique among Country records; a duplicate returns 409.
- A City must reference an existing Country (`country.id`); otherwise 404 "Country not found with id …". `GET /api/cities?countryId=` lists the cities of one Country.
- Tables are created and updated from the entities at startup (`ddl-auto: update`).

## Links with other services

This service points to no other service: it is a root of the domain.

Other services that depend on it:

- station-service: WeatherStation.cityId (City)
- observation-service: AirQuality.cityId (City)
- forecast-service: Forecast.cityId (City)
- alert-service: Alert.cityId (City)
- user-service: FavoriteLocation.cityId (City)
- report-service: Report.cityId and ReportSchedule.cityId (City)

## Configuration

`src/main/resources/application.yml`; values in `${...}` can be overridden by environment variables.

```yaml
server:
  port: 8081

spring:
  application:
    name: geo-service
  datasource:
    url: jdbc:postgresql://${DB_HOST:localhost}:5432/geo_db
    username: ${DB_USERNAME:meteo}
    password: ${DB_PASSWORD:meteo}
  jpa:
    hibernate:
      ddl-auto: update      # creates/updates the tables from the entities (dev only)
    show-sql: true
    open-in-view: false

eureka:
  client:
    service-url:
      defaultZone: ${EUREKA_URL:http://localhost:8761/eureka/}
  instance:
    prefer-ip-address: true

management:
  endpoints:
    web:
      exposure:
        include: health,info
```

| Variable | Default | Used for |
| --- | --- | --- |
| DB_HOST | localhost | database host |
| DB_USERNAME | meteo | database user |
| DB_PASSWORD | meteo | database password |
| EUREKA_URL | http://localhost:8761/eureka/ | registry address |

## Run and test

1. Start the database (`docker compose up -d` at the project root) and discovery-server.
2. Run `GeoServiceApplication` from IntelliJ, or `mvn -pl geo-service spring-boot:run` from the project root.
3. Check `http://localhost:8081/actuator/health` returns `{"status":"UP"}`, and that `GEO-SERVICE` appears on the Eureka dashboard (`http://localhost:8761`).
4. Call `GET http://localhost:8090/api/countries` through the gateway, or run the Postman folders "geo-service / Country" and "geo-service / City".
