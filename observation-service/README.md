# observation-service

observation-service stores what is measured: weather observations recorded by a station at a given time, and air quality measurements per city. It uses MongoDB because measurements arrive in bulk and their shape may grow.

## At a glance

| Item | Value |
| --- | --- |
| Owner | Member 3 |
| Entities | Observation and AirQuality |
| Stack | Java 21, Spring Boot 4.0.8, Spring Data MongoDB, Bean Validation, Eureka client |
| Port | 8083 (clients use the gateway on 8090) |
| Database | MongoDB, database `observation_db` |
| Eureka name | `observation-service` |
| REST resources | `/api/observations`, `/api/air-quality` |
| Base package | `com.meteo.observation` |

## Entities

Both entities live in package `com.meteo.observation.document`. "Required" means the field must be present and not empty in a POST or PUT body.

### Observation

Stored in collection `observations`. REST resource `/api/observations`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | string (ObjectId) | auto | generated by the database |
| stationId | long | yes | id of a WeatherStation in station-service, not checked |
| observedAt | date-time | yes | — |
| temperature | decimal | no | °C |
| humidity | decimal | no | 0.0 to 100.0; % |
| pressure | decimal | no | ≥ 0.0; hPa |
| windSpeed | decimal | no | ≥ 0.0; km/h |
| windDirection | integer | no | 0 to 360; degrees |
| precipitation | decimal | no | ≥ 0.0; mm |

### AirQuality

Stored in collection `air_quality`. REST resource `/api/air-quality`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | string (ObjectId) | auto | generated by the database |
| cityId | long | yes | id of a City in geo-service, not checked |
| measuredAt | date-time | yes | — |
| aqi | integer | yes | 0 to 500; index |
| pm25 | decimal | no | ≥ 0.0; µg/m³ |
| pm10 | decimal | no | ≥ 0.0; µg/m³ |
| o3 | decimal | no | ≥ 0.0; µg/m³ |
| no2 | decimal | no | ≥ 0.0; µg/m³ |
| level | AirQualityLevel | no | one of GOOD, MODERATE, UNHEALTHY_FOR_SENSITIVE, UNHEALTHY, VERY_UNHEALTHY, HAZARDOUS |

## REST API

Through the gateway: `http://localhost:8090`. Direct, for debugging: `http://localhost:8083`.

| Method | Path | Action | Success | Errors |
| --- | --- | --- | --- | --- |
| GET | `/api/observations` | list all; `?stationId=` filters | 200 | — |
| GET | `/api/observations/{id}` | get one Observation | 200 | 404 |
| POST | `/api/observations` | create | 201 | 400 |
| PUT | `/api/observations/{id}` | replace | 200 | 400, 404 |
| DELETE | `/api/observations/{id}` | delete | 204 | 404 |
| GET | `/api/air-quality` | list all; `?cityId=` filters | 200 | — |
| GET | `/api/air-quality/{id}` | get one AirQuality | 200 | 404 |
| POST | `/api/air-quality` | create | 201 | 400 |
| PUT | `/api/air-quality/{id}` | replace | 200 | 400, 404 |
| DELETE | `/api/air-quality/{id}` | delete | 204 | 404 |

Example: create an Observation with `POST /api/observations`

```json
{
  "stationId": 1,
  "observedAt": "2026-11-10T14:00:00",
  "temperature": 19.5,
  "humidity": 62.0,
  "pressure": 1015.2,
  "windSpeed": 14.0,
  "windDirection": 270,
  "precipitation": 0.0
}
```

Response `201 Created`:

```json
{
  "id": "6731a2f4c9e77b1d2a5e4b10",
  "stationId": 1,
  "observedAt": "2026-11-10T14:00:00",
  "temperature": 19.5,
  "humidity": 62.0,
  "pressure": 1015.2,
  "windSpeed": 14.0,
  "windDirection": 270,
  "precipitation": 0.0
}
```

## Rules and errors

- Every POST and PUT body is validated (`@Valid`); a broken rule returns 400 with the field list.
- `cityId`, `stationId` point to other services and are stored as plain numbers. This service does not check that the id exists there (an OpenFeign check can come later).
- MongoDB creates the collections on the first insert; there is no schema to migrate.

## Links with other services

This service points to:

- Observation.stationId → WeatherStation in station-service
- AirQuality.cityId → City in geo-service

Other services that depend on it:

- report-service: read to build reports (Observation and AirQuality)

## Configuration

`src/main/resources/application.yml`; values in `${...}` can be overridden by environment variables.

```yaml
server:
  port: 8083

spring:
  application:
    name: observation-service
  # Spring Boot 4: MongoDB connection properties moved from spring.data.mongodb.* to spring.mongodb.*
  mongodb:
    uri: mongodb://${DB_HOST:localhost}:27017/observation_db

eureka:
  client:
    service-url:
      defaultZone: ${EUREKA_URL:http://localhost:8761/eureka/}
  instance:
    prefer-ip-address: true

management:
  endpoints:
    web:
      exposure:
        include: health,info
```

| Variable | Default | Used for |
| --- | --- | --- |
| DB_HOST | localhost | database host |
| EUREKA_URL | http://localhost:8761/eureka/ | registry address |

## Run and test

1. Start the database (`docker compose up -d` at the project root) and discovery-server.
2. Run `ObservationServiceApplication` from IntelliJ, or `mvn -pl observation-service spring-boot:run` from the project root.
3. Check `http://localhost:8083/actuator/health` returns `{"status":"UP"}`, and that `OBSERVATION-SERVICE` appears on the Eureka dashboard (`http://localhost:8761`).
4. Call `GET http://localhost:8090/api/observations` through the gateway, or run the Postman folders "observation-service / Observation" and "observation-service / AirQuality".
