# user-service

user-service owns the people who use the app and the cities they follow: users and their favorite places, each with alerts on or off.

## At a glance

| Item | Value |
| --- | --- |
| Owner | Member 6 |
| Entities | User and FavoriteLocation |
| Stack | Java 21, Spring Boot 4.0.8, Spring Data JPA (Hibernate), Bean Validation, Eureka client |
| Port | 8086 (clients use the gateway on 8090) |
| Database | MySQL, schema `user_db` |
| Eureka name | `user-service` |
| REST resources | `/api/users`, `/api/favorites` |
| Base package | `com.meteo.user` |

## Entities

Both entities live in package `com.meteo.user.entity`. "Required" means the field must be present and not empty in a POST or PUT body.

### User

Stored in table `users`. REST resource `/api/users`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | long | auto | generated by the database |
| firstName | string | yes | max 50 characters |
| lastName | string | yes | max 50 characters |
| email | string | yes | valid email address; max 120 characters; unique |
| phone | string | no | max 20 characters |
| preferredUnit | TemperatureUnit | yes | one of CELSIUS, FAHRENHEIT; default CELSIUS |
| role | Role | yes | one of USER, ADMIN; default USER |
| createdAt | date-time | auto | set by the server at creation |

### FavoriteLocation

Stored in table `favorite_locations`. REST resource `/api/favorites`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | long | auto | generated by the database |
| cityId | long | yes | id of a City in geo-service, not checked |
| label | string | no | max 50 characters |
| alertsEnabled | boolean | no | default true |
| addedAt | date-time | auto | set by the server at creation |
| user | User | yes | send `{"id": 1}`; must exist; foreign key `user_id` |

## REST API

Through the gateway: `http://localhost:8090`. Direct, for debugging: `http://localhost:8086`.

| Method | Path | Action | Success | Errors |
| --- | --- | --- | --- | --- |
| GET | `/api/users` | list all | 200 | — |
| GET | `/api/users/{id}` | get one User | 200 | 404 |
| POST | `/api/users` | create | 201 | 400, 409 |
| PUT | `/api/users/{id}` | replace | 200 | 400, 404, 409 |
| DELETE | `/api/users/{id}` | delete | 204 | 404, 409 |
| GET | `/api/favorites` | list all; `?userId=` filters | 200 | — |
| GET | `/api/favorites/{id}` | get one FavoriteLocation | 200 | 404 |
| POST | `/api/favorites` | create | 201 | 400, 404 |
| PUT | `/api/favorites/{id}` | replace | 200 | 400, 404 |
| DELETE | `/api/favorites/{id}` | delete | 204 | 404 |

Example: create a User with `POST /api/users`

```json
{
  "firstName": "Amira",
  "lastName": "Ben Salah",
  "email": "amira.bensalah@example.com",
  "phone": "+21620000000",
  "preferredUnit": "CELSIUS",
  "role": "USER"
}
```

Response `201 Created`:

```json
{
  "id": 1,
  "firstName": "Amira",
  "lastName": "Ben Salah",
  "email": "amira.bensalah@example.com",
  "phone": "+21620000000",
  "preferredUnit": "CELSIUS",
  "role": "USER",
  "createdAt": "2026-11-11T09:15:42"
}
```

Example: create a FavoriteLocation with `POST /api/favorites`

```json
{
  "cityId": 1,
  "label": "Home",
  "alertsEnabled": true,
  "user": {
    "id": 1
  }
}
```

Response `201 Created`:

```json
{
  "id": 1,
  "cityId": 1,
  "label": "Home",
  "alertsEnabled": true,
  "user": {
    "id": 1,
    "firstName": "Amira",
    "lastName": "Ben Salah",
    "email": "amira.bensalah@example.com",
    "phone": "+21620000000",
    "preferredUnit": "CELSIUS",
    "role": "USER",
    "createdAt": "2026-11-11T09:10:05"
  },
  "addedAt": "2026-11-11T09:15:42"
}
```

## Rules and errors

- Every POST and PUT body is validated (`@Valid`); a broken rule returns 400 with the field list.
- A User that still has favorite locations cannot be deleted: 409 Conflict. Delete the favorite locations first.
- `email` must be unique among User records; a duplicate returns 409.
- `createdAt` of User is set by the server; a value sent by the client is ignored.
- A FavoriteLocation must reference an existing User (`user.id`); otherwise 404 "User not found with id …". `GET /api/favorites?userId=` lists the favorites of one User.
- `addedAt` of FavoriteLocation is set by the server; a value sent by the client is ignored.
- `cityId` points to another service and is stored as a plain number. This service does not check that the id exists there (an OpenFeign check can come later).
- Tables are created and updated from the entities at startup (`ddl-auto: update`).

## Configuration

`src/main/resources/application.yml`; values in `${...}` can be overridden by environment variables.

```yaml
server:
  port: 8086

spring:
  application:
    name: user-service
  datasource:
    url: jdbc:mysql://${DB_HOST:localhost}:3306/user_db?createDatabaseIfNotExist=true&allowPublicKeyRetrieval=true&useSSL=false
    username: ${DB_USERNAME:meteo}
    password: ${DB_PASSWORD:meteo}
  jpa:
    hibernate:
      ddl-auto: update      # creates/updates the tables from the entities (dev only)
    show-sql: true
    open-in-view: false

eureka:
  client:
    service-url:
      defaultZone: ${EUREKA_URL:http://localhost:8761/eureka/}
  instance:
    prefer-ip-address: true

management:
  endpoints:
    web:
      exposure:
        include: health,info
```

| Variable | Default | Used for |
| --- | --- | --- |
| DB_HOST | localhost | database host |
| DB_USERNAME | meteo | database user |
| DB_PASSWORD | meteo | database password |
| EUREKA_URL | http://localhost:8761/eureka/ | registry address |

## Run and test

1. Start the database (`docker compose up -d` at the project root) and discovery-server.
2. Run `UserServiceApplication` from IntelliJ, or `mvn -pl user-service spring-boot:run` from the project root.
3. Check `http://localhost:8086/actuator/health` returns `{"status":"UP"}`, and that `USER-SERVICE` appears on the Eureka dashboard (`http://localhost:8761`).
4. Call `GET http://localhost:8090/api/users` through the gateway, or run the Postman folders "user-service / User" and "user-service / FavoriteLocation".
