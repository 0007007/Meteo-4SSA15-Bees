# station-service

station-service owns the measuring equipment: weather stations placed in a city and the sensors installed on each station. Observations from observation-service point to a station by its id.

## At a glance

| Item | Value |
| --- | --- |
| Owner | Aziz Kchaou |
| Entities | WeatherStation and Sensor |
| Stack | Java 21, Spring Boot 4.0.8, Spring Data JPA (Hibernate), Bean Validation, Eureka client |
| Port | 8082 (clients use the gateway on 8090) |
| Database | PostgreSQL, schema `station_db` |
| Eureka name | `station-service` |
| REST resources | `/api/stations`, `/api/sensors` |
| Base package | `com.meteo.station` |

## Entities

Both entities live in package `com.meteo.station.entity`. "Required" means the field must be present and not empty in a POST or PUT body.

### WeatherStation

Stored in table `weather_stations`. REST resource `/api/stations`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | long | auto | generated by the database |
| code | string | yes | max 20 characters; unique |
| name | string | yes | max 100 characters |
| latitude | decimal | yes | -90.0 to 90.0; decimal degrees |
| longitude | decimal | yes | -180.0 to 180.0; decimal degrees |
| altitude | decimal | no | metres |
| installationDate | date | no | — |
| status | StationStatus | yes | one of ACTIVE, MAINTENANCE, INACTIVE; default ACTIVE |
| cityId | long | yes | id of a City in geo-service, not checked |

### Sensor

Stored in table `sensors`. REST resource `/api/sensors`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | long | auto | generated by the database |
| serialNumber | string | yes | max 50 characters; unique |
| type | SensorType | yes | one of TEMPERATURE, HUMIDITY, PRESSURE, WIND_SPEED, WIND_DIRECTION, PRECIPITATION, UV |
| unit | string | no | max 20 characters |
| lastCalibrationDate | date | no | — |
| active | boolean | no | default true |
| station | WeatherStation | yes | send `{"id": 1}`; must exist; foreign key `station_id` |

## REST API

Through the gateway: `http://localhost:8090`. Direct, for debugging: `http://localhost:8082`.

| Method | Path | Action | Success | Errors |
| --- | --- | --- | --- | --- |
| GET | `/api/stations` | list all; `?cityId=` filters | 200 | — |
| GET | `/api/stations/{id}` | get one WeatherStation | 200 | 404 |
| POST | `/api/stations` | create | 201 | 400, 409 |
| PUT | `/api/stations/{id}` | replace | 200 | 400, 404, 409 |
| DELETE | `/api/stations/{id}` | delete | 204 | 404, 409 |
| GET | `/api/sensors` | list all; `?stationId=` filters | 200 | — |
| GET | `/api/sensors/{id}` | get one Sensor | 200 | 404 |
| POST | `/api/sensors` | create | 201 | 400, 404, 409 |
| PUT | `/api/sensors/{id}` | replace | 200 | 400, 404, 409 |
| DELETE | `/api/sensors/{id}` | delete | 204 | 404 |

Example: create a WeatherStation with `POST /api/stations`

```json
{
  "code": "TUN-001",
  "name": "Tunis-Carthage station",
  "latitude": 36.851,
  "longitude": 10.227,
  "altitude": 4.0,
  "installationDate": "2020-03-15",
  "status": "ACTIVE",
  "cityId": 1
}
```

Response `201 Created`:

```json
{
  "id": 1,
  "code": "TUN-001",
  "name": "Tunis-Carthage station",
  "latitude": 36.851,
  "longitude": 10.227,
  "altitude": 4.0,
  "installationDate": "2020-03-15",
  "status": "ACTIVE",
  "cityId": 1
}
```

Example: create a Sensor with `POST /api/sensors`

```json
{
  "serialNumber": "SN-TMP-0001",
  "type": "TEMPERATURE",
  "unit": "°C",
  "lastCalibrationDate": "2026-09-01",
  "active": true,
```

## Rules and errors

- Every POST and PUT body is validated (`@Valid`); a broken rule returns 400 with the field list.
- A WeatherStation that still has sensors cannot be deleted: 409 Conflict. Delete the sensors first.
- `code` must be unique among WeatherStation records; a duplicate returns 409.
- A Sensor must reference an existing WeatherStation (`station.id`); otherwise 404 "WeatherStation not found with id …". `GET /api/sensors?stationId=` lists the sensors of one WeatherStation.
- `serialNumber` must be unique among Sensor records; a duplicate returns 409.
- `cityId` points to another service and is stored as a plain number. This service does not check that the id exists there (an OpenFeign check can come later).
- Tables are created and updated from the entities at startup (`ddl-auto: update`).

## Links with other services

This service points to:

- WeatherStation.cityId → City in geo-service

- observation-service: Observation.stationId (WeatherStation)

## Configuration

`src/main/resources/application.yml`; values in `${...}` can be overridden by environment variables.

```yaml
server:
  port: 8082

spring:
  application:
    name: station-service
  datasource:
    url: jdbc:postgresql://${DB_HOST:localhost}:5432/station_db
    username: ${DB_USERNAME:meteo}
    password: ${DB_PASSWORD:meteo}
  jpa:
    hibernate:
      ddl-auto: update      # creates/updates the tables from the entities (dev only)
    show-sql: true
    open-in-view: false

eureka:
  client:
    service-url:
      defaultZone: ${EUREKA_URL:http://localhost:8761/eureka/}
  instance:
    prefer-ip-address: true

management:
  endpoints:
    web:
      exposure:
        include: health,info
```

| Variable | Default | Used for |
| --- | --- | --- |
| DB_HOST | localhost | database host |
| DB_USERNAME | meteo | database user |
| DB_PASSWORD | meteo | database password |
| EUREKA_URL | http://localhost:8761/eureka/ | registry address |

## Run and test

1. Start the database (`docker compose up -d` at the project root) and discovery-server.
2. Run `StationServiceApplication` from IntelliJ, or `mvn -pl station-service spring-boot:run` from the project root.
3. Check `http://localhost:8082/actuator/health` returns `{"status":"UP"}`, and that `STATION-SERVICE` appears on the Eureka dashboard (`http://localhost:8761`).
4. Call `GET http://localhost:8090/api/stations` through the gateway, or run the Postman folders "station-service / WeatherStation" and "station-service / Sensor".
