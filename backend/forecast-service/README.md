# forecast-service

forecast-service stores what is predicted: daily forecasts per city and the numerical models that produce them. Both are MongoDB documents; a forecast points to its model by the model's id.

## At a glance

| Item | Value |
| --- | --- |
| Owner | Member 4 |
| Entities | ForecastModel and Forecast |
| Stack | Java 21, Spring Boot 4.0.8, Spring Data MongoDB, Bean Validation, Eureka client |
| Port | 8084 (clients use the gateway on 8090) |
| Database | MongoDB, database `forecast_db` |
| Eureka name | `forecast-service` |
| REST resources | `/api/forecast-models`, `/api/forecasts` |
| Base package | `com.meteo.forecast` |

## Entities

Both entities live in package `com.meteo.forecast.document`. "Required" means the field must be present and not empty in a POST or PUT body.

### ForecastModel

Stored in collection `forecast_models`. REST resource `/api/forecast-models`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | string (ObjectId) | auto | generated by the database |
| name | string | yes | max 50 characters |
| provider | string | no | max 100 characters |
| version | string | no | max 20 characters |
| resolutionKm | decimal | no | ≥ 0.0; km |
| horizonDays | integer | no | 1 to 30; days |
| description | string | no | max 500 characters |

### Forecast

Stored in collection `forecasts`. REST resource `/api/forecasts`.

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| id | string (ObjectId) | auto | generated by the database |
| cityId | long | yes | id of a City in geo-service, not checked |
| forecastDate | date | yes | — |
| minTemperature | decimal | no | °C |
| maxTemperature | decimal | no | °C |
| condition | WeatherCondition | yes | one of SUNNY, PARTLY_CLOUDY, CLOUDY, RAIN, THUNDERSTORM, SNOW, FOG, WINDY, SANDSTORM |
| precipitationProbability | integer | no | 0 to 100; % |
| windSpeed | decimal | no | ≥ 0.0; km/h |
| modelId | string | yes | id of an existing ForecastModel |
| createdAt | date-time | auto | set by the server at creation |

## REST API

Through the gateway: `http://localhost:8090`. Direct, for debugging: `http://localhost:8084`.

| Method | Path | Action | Success | Errors |
| --- | --- | --- | --- | --- |
| GET | `/api/forecast-models` | list all | 200 | — |
| GET | `/api/forecast-models/{id}` | get one ForecastModel | 200 | 404 |
| POST | `/api/forecast-models` | create | 201 | 400 |
| PUT | `/api/forecast-models/{id}` | replace | 200 | 400, 404 |
| DELETE | `/api/forecast-models/{id}` | delete | 204 | 404, 409 |
| GET | `/api/forecasts` | list all; `?cityId=` filters | 200 | — |
| GET | `/api/forecasts/{id}` | get one Forecast | 200 | 404 |
| POST | `/api/forecasts` | create | 201 | 400, 404 |
| PUT | `/api/forecasts/{id}` | replace | 200 | 400, 404 |
| DELETE | `/api/forecasts/{id}` | delete | 204 | 404 |

Example: create a ForecastModel with `POST /api/forecast-models`

```json
{
  "name": "GFS",
  "provider": "NOAA",
  "version": "16",
  "resolutionKm": 13.0,
  "horizonDays": 16,
  "description": "Global Forecast System"
}
```

Response `201 Created`:

```json
{
  "id": "6731a2f4c9e77b1d2a5e4b10",
  "name": "GFS",
  "provider": "NOAA",
  "version": "16",
  "resolutionKm": 13.0,
  "horizonDays": 16,
  "description": "Global Forecast System"
}
```

Example: create a Forecast with `POST /api/forecasts`

```json
{
  "cityId": 1,
  "forecastDate": "2026-11-11",
  "minTemperature": 14.0,
  "maxTemperature": 21.0,
  "condition": "PARTLY_CLOUDY",
  "precipitationProbability": 20,
  "windSpeed": 18.0,
  "modelId": "6731a2f4c9e77b1d2a5e4b0f"
}
```

Response `201 Created`:

```json
{
  "id": "6731a2f4c9e77b1d2a5e4b10",
  "cityId": 1,
  "forecastDate": "2026-11-11",
  "minTemperature": 14.0,
  "maxTemperature": 21.0,
  "condition": "PARTLY_CLOUDY",
  "precipitationProbability": 20,
  "windSpeed": 18.0,
  "modelId": "6731a2f4c9e77b1d2a5e4b0f",
  "createdAt": "2026-11-11T09:15:42"

```

## Rules and errors

- Every POST and PUT body is validated (`@Valid`); a broken rule returns 400 with the field list.
- A ForecastModel that still has forecasts cannot be deleted: 409 Conflict. Delete the forecasts first.
- A Forecast must reference an existing ForecastModel through `modelId`; otherwise 404.
- `createdAt` of Forecast is set by the server; a value sent by the client is ignored.
- `cityId` points to another service and is stored as a plain number. This service does not check that the id exists there (an OpenFeign check can come later).
- MongoDB creates the collections on the first insert; there is no schema to migrate.

## Configuration

`src/main/resources/application.yml`; values in `${...}` can be overridden by environment variables.

```yaml
server:
  port: 8084

spring:
  application:
    name: forecast-service
  # Spring Boot 4: MongoDB connection properties moved from spring.data.mongodb.* to spring.mongodb.*
  mongodb:
    uri: mongodb://${DB_HOST:localhost}:27017/forecast_db

eureka:
  client:
    service-url:
      defaultZone: ${EUREKA_URL:http://localhost:8761/eureka/}
  instance:
    prefer-ip-address: true

management:
  endpoints:
    web:
      exposure:
        include: health,info
```

| Variable | Default | Used for |
| --- | --- | --- |
| DB_HOST | localhost | database host |
| EUREKA_URL | http://localhost:8761/eureka/ | registry address |

## Run and test

1. Start the database (`docker compose up -d` at the project root) and discovery-server.
2. Run `ForecastServiceApplication` from IntelliJ, or `mvn -pl forecast-service spring-boot:run` from the project root.
3. Check `http://localhost:8084/actuator/health` returns `{"status":"UP"}`, and that `FORECAST-SERVICE` appears on the Eureka dashboard (`http://localhost:8761`).
4. Call `GET http://localhost:8090/api/forecast-models` through the gateway, or run the Postman folders "forecast-service / ForecastModel" and "forecast-service / Forecast".
